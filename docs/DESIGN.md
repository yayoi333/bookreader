# よみあげ文庫 → SuperFlow化 設計書

作成: 2026-10-12 / 対象: `yayoi333/bookreader`（2026-10-10 時点のコード）

## 1. 目指すもの

SuperFlow（保存 → AIが自動要約 → 要約で下読み・耳で聴く → 読んだものがAIの「第二の脳」になる）を、
**Windows ＋ Android** で、**月額0円**で使える自分専用版にする。

SuperFlow に無くて、こちらにあるもの（守る強み）:

- Android で使える（SuperFlow の音声は iOS アプリだけ）
- 画面オフでも聴けるクラウド音声と、無料の端末の声の2方式
- データは自分の Google Drive。サービス終了の心配がない

## 2. 決まっていること（2026-10-12 ユーザー回答）

| 項目 | 決定 |
|---|---|
| 要約AI | Gemini API の無料枠 |
| 置き場所 | Google Drive（今の GAS 連携を延長する） |
| 読み上げ | 今の2方式（端末の声／クラウド音声）をそのまま使う |
| 進め方 | まず設計書。実装は後日フェーズごとに |
| Googleアカウント | **info@threeehearts.com** で GAS を作り直す（PC の Google ドライブもこのアカウント。旧版もここにある） |
| APIキー | 平文で端末に置かない。TTS のキーは GAS のスクリプトプロパティへ、GAS のトークンは端末内で暗号化（v0.2.0 で実装済み） |
| 旧版 | 新版へ引っ越す（GAS の `importOldLibrary`。v0.2.0 で実装済み） |
| AIの読み方 | 毎回全文を読まない。目次（INDEX.md）を先に読み、必要な記事だけ開く |

## 4. 足すもの（SuperFlowとの差分）

### A. 保存と同時にAI要約 【中心機能】

- **呼び出し場所は GAS**。Gemini の APIキーは GAS のスクリプトプロパティに置く。
  ブラウザ（localStorage）にキーを置かないので、どの端末から保存しても同じキーで要約され、キーも漏れにくい。
- GAS に `summarize` 操作を追加する。入力は記事の blocks、出力は次の JSON。
  ```json
  {
    "tldr": "1〜2文の結論",
    "points": ["要点1", "要点2", "要点3"],
    "terms": [{ "word": "難しい用語", "note": "ひとこと解説" }],
    "verdict": { "level": "高 | 中 | 低", "reason": "全文を読む価値の理由を1文" },
    "model": "使ったモデル名",
    "truncated": false,
    "at": 1760000000000
  }
  ```
- 記事に `summary` 欄を追加し、端末内（IndexedDB）と Drive の両方に保存する。
- 流れ: 取り込み → 本棚に保存（今まで通り）→ 裏で `summarize` → 要約が届いたら記事を更新。
  失敗しても記事は残す。記事画面に「要約する／作り直す」ボタンを置く。
- 長すぎる記事は、先頭から一定文字数で切って要約する（上限は実装時に Gemini の入力上限から決める）。
- モデルは GAS のスクリプトプロパティ `GEMINI_MODEL` で変えられる。無ければ `gemini-3.5-flash-lite`
  （2026-10-09 更新の公式資料で、無料枠あり・低コスト大量処理向けの安定版）。回数制限は公式資料に数値が無く、AI Studio の画面でだけ見られる。
- **無料枠では、送った記事の内容が Google の製品改善に使われる**（公式の料金表に明記。有料枠では使われない）。
  有料記事や非公開のメモを要約に送るかどうかは利用者が判断する。
- 無料枠を超えたときは「今日は要約の上限です」と表示し、翌日に「要約する」で再実行できるようにする。

### B. 要約を聴く／まとめて聴く

- 記事画面に「要約／本文」の切り替えを付ける。要約は blocks に変換して、今のプレーヤーで読む
  （`buildSegments` がそのまま使える。音声キャッシュはテキストのハッシュが鍵なので混ざらない）。
- 本棚に「未読の要約をまとめて聴く」を付ける。未読の記事の要約を新しい順に連続再生し、
  1件終わるごとにタイトルを読んでから次へ進む。通勤・家事の時間にまとめて消化するための機能。
- 画面オフで続けて聴くにはクラウド音声が必要（今の README の比較表どおり）。

### C. カードで消化する（下読み）

- 本棚の各記事に、要約の `tldr` と `verdict` を2〜3行で表示する。
- 状態を3つ持つ: 未読 / あとで全文 / 読了。本棚の上で絞り込める。
- PC では J/K で前後の記事、E で読了、Space で再生／停止。

### D. Claude Code / Codex から読める「第二の脳」

- GAS の `save` で、Googleドキュメントに加えて **Markdown ファイル** も `よみあげ文庫/md/` に保存する。
  理由: PC の Google ドライブ（ストリーミング）では、Googleドキュメントは本文を持たないショートカットファイル（.gdoc）として
  見えるはずで、Claude Code が中身を読めない（このPCでは .gdoc の実物が見つからず未確認。フェーズ5の最初に実測する）。
  Markdown なら grep や Read で直接読める。
- Markdown の形（先頭にメタ情報、続けて要約、本文）:
  ```markdown
  ---
  title: 記事タイトル
  url: https://...
  author: 著者
  saved: 2026-10-12
  status: 未読 | あとで | 読了
  tags: [X, AI]
  ---
  ## 要約
  ...
  ## 本文
  ...
  ```
- **目次 `よみあげ文庫/md/INDEX.md` を GAS が自動で作り直す**（保存・要約・状態変更・引っ越しのたび）。
  1記事1行で、全文は入れない。
  ```markdown
  | 保存日 | タイトル | タグ | 状態 | 要約1行 | ファイル |
  |---|---|---|---|---|---|
  | 2026-10-12 | 記事タイトル | X, AI | 未読 | 1行の結論 | 20261012-記事タイトル.md |
  ```
  記事が数百本になっても、1行あたり150字程度なら目次は数万字に収まる。増えすぎたら年ごとに `INDEX-2026.md` へ分ける。
- Claude Code 側は、次の読み方を書いた小さなスキル（またはメモリ）を用意する。
  1. まず `INDEX.md` だけを読む
  2. 質問に関係する行を選び、その記事の md だけを開く（まず「## 要約」まで、足りなければ本文）
  3. フォルダの md を全部読む・全文を grep して全部開く、はしない
  専用CLIは作らない。
- SuperFlow と同じく、AI からは**読むだけ**にする（削除・書き換えはアプリ側でだけ行う）。

## 7. 実装済み

### フェーズ4（v0.5.0, 2026-10-13）
- 記事に `status`（unread / later / done）と `statusAt`。未設定の古い記事は、本文を聴き終えていれば読了、それ以外は未読として扱う（`statusOf`）。
- 本文を最後まで聴き終えたら自動で読了。要約・まとめて聴くの再生では変えない。
- 本棚：未読／あとで／読了／すべて の絞り込み（件数つき、端末に記憶、最初は「すべて」）。各記事に「あとで」「読了」ボタン（押し直すと未読に戻る）。
- 記事画面：「読了にする／未読に戻す」「あとで／あとでを外す」。
- キー操作（PC、入力中は無効）：本棚 J/K 選択・E 読了・L あとで・Enter/O 開く。記事画面 J/K 次・前（本棚の絞り込みの並び）、E 読了にして次へ、L あとで、Esc 本棚。どこでも Space 再生／一時停止。
- 「まとめて聴く」の対象は status が未読の記事だけ。

### フェーズ3（v0.4.0, 2026-10-13）
- 要約は「読み上げ用の仮の記事」に組み立てて、いつもの再生機能で読む（速度・ロック画面操作・クラウド音声の先読みとキャッシュがそのまま効く）。本棚には保存しない。
- 記事画面の「要約を聴く」：結論→要点→用語→全文を読む価値。▶（本文）を押すと本文に戻る。要約再生中は本文のハイライトを動かさない。
- 本棚の「未読の要約をまとめて聴く（N本）」：未読＝本文を最後まで聴き終えていない記事。新しい順に最大20本、各記事「◯本目。タイトル」→結論→要点→評価（用語は省く）。
- 要約を再生している最中は、記事画面を開いても再生を止めない（普通の記事どうしは従来どおり切り替わる）。
- 要約の聴き途中の位置は保存しない（短いため）。

### フェーズ2（v0.3.0, 2026-10-12）
- 取り込み保存のあと、Drive連携が設定されていれば裏で `summarize` を呼ぶ。本文が変わったら古い要約を捨てる。
- 記事画面の見出しと本文の間に「AI要約」欄（結論・要点・用語・全文を読む価値）。失敗時は理由と「もう一度要約する」、成功後は「作り直す」。
- 本棚の各記事に、評価バッジ＋結論を2行まで表示。
- 要約は**この端末（IndexedDB）にだけ**保存。別の端末では作り直しになる。Drive への保存はフェーズ5の Markdown 書き出しでまとめて行う。
- Drive保存・要約・読書位置の書き込みが同時に走っても上書きし合わないよう、記事の更新を1回の読み書き（`docs.update`）にまとめた。
- Drive から開いた記事（引っ越した23本を含む）は自動では要約しない。記事画面の「AIで要約する」で1本ずつ要約する。

### フェーズ1（2026-10-12）
- GAS に `summarize` 操作と `summarize_` を追加。`GEMINI_API_KEY` はスクリプトプロパティにだけ置き、URLではなくヘッダーで送る。
- 出力の型指定（responseSchema）を断られたら、型指定なしで1回だけ再試行。返事は必ず形チェックして整える。
- 無料枠切れ（429）は `error: 'summary_quota'` で返す。どの失敗も例外にせず `{ ok: false }` で返すので、記事の保存は止まらない。
- GAS エディタで `testSummarize` を実行すると、最新の記事の要約がログに出る（実データでの確認用）。

### v0.2.0（2026-10-12）

- クラウド音声の生成を GAS 経由にした（`gas/Code.gs` の `tts_` / `voices_`）。APIキーは GAS のスクリプトプロパティ `TTS_API_KEY`。
  アプリに APIキーの入力欄は無く、旧版で端末に保存されたキーは起動時に消す（`js/settings.js` の `migrateSecrets`）。
- GAS のトークンは、取り出し不可の Web Crypto 鍵（IndexedDB）で AES-GCM 暗号化して保存（`js/secret.js`）。設定画面に値を戻さない。
- 旧版の引っ越し `importOldLibrary`（旧フォルダは読むだけ）。
- 注意: TTS を GAS 経由にしたので、APIキーの「ウェブサイトの制限」は外す必要がある（GAS からの呼び出しには参照元が無い）。
  キーは Google のサーバー側にしか無いので、制限を外しても漏れる経路は増えない。API の制限（Text-to-Speech のみ）は残す。
